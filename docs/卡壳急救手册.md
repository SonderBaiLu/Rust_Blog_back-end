# 卡壳急救手册：完全不会写时怎么办

> 定位：`docs/学习计划.md` 的分支系统（B1–B15）解决「卡在某概念上」；
> 本手册解决更前面的状态——**面对一个任务，完全不知道从哪下笔**。
>
> 核心信念：「完全不会写」几乎从不等于「你不适合」，它等于**知识链上断了一环**。
> 本手册的工作就是帮你找到断点，补上它，然后回到原任务。
>
> 用法：卡住 → 第 1 节分型（5 分钟）→ 查第 9 节知识总表 → 限时补知识 → 写最小例子验证 →
> 记入 `docs/踩坑记录.md` → 回到原任务。全程不超过半天。

---

## 1. 先分型：你是哪种「不会写」

对着任务问自己四个问题，按顺序判断，**命中即停**：

| 顺序 | 自测问题 | 命中 → 类型 |
| --- | --- | --- |
| ① | 我能不能用大白话说出「这件事要做什么」？ | 不能 → **C 设计型**（最严重，最常见） |
| ② | 我能不能写出伪代码（不关心语法的步骤）？ | 不能但①能 → 也是 **C 设计型** |
| ③ | 伪代码里的每一步，我都知道用什么语法/哪个 API 实现吗？ | 不知道语法 → **A 语法型**；不知道用哪个库/方法 → **B API 型** |
| ④ | 我写出来了，但 `cargo check` 一报错就懵、不敢再编译？ | 是 → **D 编译器型**（常和 A/E 叠加） |

另外独立一类：**E 概念型**——语法会写，但底层概念（所有权 / async / trait 对象）没懂，
所以「写得出来但永远写不对」。判断方法：这个概念你能不能教给别人？不能 → E 型，
直接走 `docs/学习计划.md` 第五章对应的分支（B1–B15），本手册不重复分支内容。

**分型完成后的动作**：在 `docs/踩坑记录.md` 记一行——
`日期 | 任务 | 类型（A/B/C/D/E）| 断点在哪`。这一行本身就是诊断结果。

---

## 2. A 型：语法缺口（知道做什么，写不出语法）

**需要的知识清单**（逐项自测，写不出来的就是断点）：

- [ ] 模块系统：`mod` / `pub` / `use` / `super`，跨文件引用怎么写
- [ ] 所有权基础：`&T` / `&mut T` / 移动，函数参数和返回值怎么写
- [ ] 泛型：`fn f<T>(x: T)`、`where T: Trait` 边界、结构体带泛型
- [ ] trait：定义 trait、给结构体 impl、`dyn Trait` 放在哪
- [ ] 生命周期：`'a` 标在哪个位置（三条省略规则）
- [ ] enum + match：带数据的枚举、穷尽匹配
- [ ] Option / Result 常用方法：`map` / `and_then` / `unwrap_or` / `?`
- [ ] async 语法：`async fn`、`.await`、`#[tokio::main]`
- [ ] 闭包：`|x| ...`、捕获、`move`
- [ ] derive 宏：`#[derive(Debug, Clone, Serialize)]` 的写法

**去哪补**：《Rust 编程之旅》中文版（搜「Rust 编程之旅」，GitHub 有完整中文版），
按上面清单对应章节读：**模块=第 7 章，所有权=第 4 章，泛型/trait=第 10 章，
生命周期=第 10 章末，闭包=第 13 章，async=第 17 章**。只读缺的那章，不全读。

**出口标准**：合上书，把清单里缺项对应的语法各写一个最小例子，`cargo check` 通过。

---

## 3. B 型：API 缺口（知道语法，不知道用哪个库 / 方法）

**方法：三步找 API**

1. **一句话说清能力**：把需求压成一句「我要________」（例：「我要校验 URL 格式」）。
2. **先查项目再查外网**：
   - 先看 `Cargo.toml`——项目里很可能已有依赖能做这件事（你项目里 `validator`
     就能做字段校验，`chrono` 能做时间，`uuid` 能做 ID）。
   - 再查 `docs/学习计划.md` 第四章工具包——85 个方法清单就是为你准备的，
     按分类找（时间→4.11，校验→4.10 附近，异步→4.7）。
   - 最后搜「Rust + 能力关键词 + 中文」（例：「Rust 校验 URL crate 中文」）。
3. **找到后不背，记用法**：写一个 3 行用法例子，追加到 `docs/学习内容.md`，
   格式：`能力一句话 | crate::方法 | 3 行例子 | 用在哪`。

**需要的知识**：不是「背 API」，是**能力→工具映射表**。工具包清单勾满 85 项，
B 型卡壳基本绝迹。

**出口标准**：随机抽 5 个常见能力（解析 JSON / 生成 UUID / 校验邮箱 / 异步 sleep /
读环境变量），1 分钟内说出用哪个 crate 的哪个方法。

## 4. C 型：设计缺口（连「做什么」都说不清）⭐ 最重要

这是「完全不会写」的高发区，也是**设计层能力**（你一年计划的目标层）的直接训练场。

**方法：设计五问**（答不出哪一问，哪一问就是你的断点）：

1. **数据**：涉及哪些字段？存哪张表？哪些可空？
2. **入口**：谁调用它？HTTP 方法 + 路径 + 请求体 + 返回体是什么？
3. **分层**：每步逻辑放五层的哪一层？（校验→DTO/handler，业务→service，SQL→postgres）
4. **错误**：哪些情况会失败？各自返回哪个 `AppError` 变体？
5. **测试**：写哪 3 个测试用例能证明它对了？

五问全答上 → 你可以开始写了（哪怕语法还不熟，那只是 A 型问题）。
答不上 → 缺的知识就是答不上的那一问，见下表：

| 答不上的问题 | 缺的知识 | 去哪补 |
| --- | --- | --- |
| 数据 | 表设计基本规则（主键 / 外键 / 软删除 / 时间字段） | 看 `migrations/` 里现有的 4 个迁移文件当范例 |
| 入口 | REST 资源建模 | 看 `docs/openapi.yaml` 现有 10 个端点的命名规律 |
| 分层 | 五层职责边界 | **第 1 周【深】任务：`docs/post模块职责清单.md`（就是为这个准备的）** |
| 错误 | 错误体系设计 | 第 3 周【深】任务：`docs/post错误矩阵.md` |
| 测试 | 测试基本结构 | B8 分支（`docs/学习计划.md` 5.3 节） |

**辅助方法：仿写**。设计不会时，打开项目里最像的已有模块（比如要写「列表」，
就看 `src/modules/todo/` 的列表怎么走的：route→handler→service→postgres 一路跟），
先照抄结构再换业务。**仿写不丢人，它是设计的起点不是终点**——仿完必须回答：
「哪里我改成了不一样的？为什么？」答不出来说明还是没懂。

**出口标准**：能给一个新功能写出一页设计文档（表结构 / 端点 / 五层职责 / 错误分支 /
测试计划），`docs/设计-xxx.md` 格式，和计划里方法 4 一致。

## 5. D 型：编译器恐惧（写得出来，不敢编译 / 报错就懵）

**核心认知**：编译器错误是**信息量最高的老师**，它每次都告诉你三件事：
错在哪（下划线 span）、是什么错（错误码）、往往还有修复建议（help 段）。

**读错三步法**：
1. 找**第一个**错误（后面的错常常是它引起的连锁反应）；
2. 读错误码 + 一句话描述；
3. 看 span 指向的那行，对照下表定位缺的知识。

**常见错误码速查**：

| 错误码 | 一句话含义 | 通常缺的知识 |
| --- | --- | --- |
| E0308 | 类型不匹配 | 类型系统 / 泛型（§2 清单） |
| E0425 / E0432 | 找不到变量 / 类型 / 模块 | 模块系统（`use` 没写对） |
| E0392 | 缺泛型参数 | 泛型 |
| E0277 | 不满足 trait 约束 | trait 边界 / `where` 写法 |
| E0499 | 不能可变借用（已有别的借用） | 所有权（→ B1 分支） |
| E0382 | 移动后还在用 | 所有权（→ B1 分支） |
| E0597 / E0271 | 借用活得太短 / 生命周期不满足 | 生命周期（→ B12 分支） |
| E0658 | 不稳定特性 | 该特性需 nightly（了解即可） |

**训练方法**：计划里的「方法 2 预测先行」——每次 `cargo check` 前先写下
「我认为会报 N 个错，分别是……」，编译核对。猜错的每条都是一个精确的知识缺口，
记入 `docs/学习内容.md`。

**出口标准**：看到任意一个编译错误，30 秒内说出「它缺的是哪一层知识」并指到本手册对应小节。

## 6. E 型：概念缺口 → 直接走分支

语法会、概念不懂，分支系统就是为这个建的。快查表（详情在 `docs/学习计划.md` 5.3 节）：

| 你卡住的感受 | 走哪个分支 |
| --- | --- |
| 「我不能改这个变量？为什么？」 | B1 所有权与借用 |
| 「`?` 到底干了啥」 | B2 Result / 错误传播 |
| 「`dyn` 和泛型到底差在哪」 | B3 泛型 vs trait object |
| 「`Arc` 去掉会怎样」 | B4 Arc 与共享状态 |
| 「`.await` 之后代码去哪了」 | B5 async 任务调度（全计划最重要） |
| 「提取器是怎么被调用的」 | B6 axum 提取器机制 |
| 「`query_as` 怎么把列变字段的」 | B7 sqlx 宏机制 |
| 「测试怎么不连数据库」 | B8 测试与 mock |
| 「`'a` 该标在哪」 | B12 生命周期标注 |
| 「trait 该长什么样」 | B13 trait 设计 |

规矩照旧：触发题自测 → 限时 → 出口题口述 → 记 `docs/踩坑记录.md`。

## 7. 最小可写单元法（所有类型通用的下笔技术）

面对「完全不会写」的任务，**永远不要试图一次写完**。把它缩到最小：

**第 1 步：只写签名**。函数签名 + 参数 + 返回类型，函数体 `todo!()`。
```rust
// 例：要写 list_posts，先只到这一步
async fn list_posts(&self, query: PostQuery) -> Result<Paginated<PostListItemResp>, AppError> {
    todo!()
}
```
签名能编译 = 你对「输入输出」的理解已经成立了一半。

**第 2 步：一次填一行，一行一编译**。每填一行跑一次 `cargo check`，
让编译器当逐行老师（配合 §5 读错三步法）。

**第 3 步：借结构**。`grep` 项目里最相似的已有实现，**抄结构不抄值**——
调用链的形状（handler 调 service 调 repo）照搬，业务内容自己填。

**第 4 步：先写一个测试**。哪怕实现是 `todo!()`，先把「期望它做什么」写成
一个必然失败的测试。测试写出来了 = 你其实知道它该做什么，剩下的只是实现。

**卡死信号**：第 1 步的签名都写不出来 → 这不是下笔问题，是 C 型设计缺口，
回 §4 做设计五问。

## 8. 求助时机与方式

- **卡超 30 分钟**才求助（计划第八章纪律 4），30 分钟内自己挣扎是学习本身。
- 求助 AI 用 `docs/学习计划.md` 第十章协议：**要提示不要代写**——
  「给我接口签名 / 测试用例设计 / 方向」，不要「把函数体写了」。
- 搜索公式：`Rust + 概念 + 中文`；报错就加错误码（`Rust E0597 中文`）。
- **最卡的信号**：你连「问题是什么」都说不成一句话 → 停下，回 §1 重新分型。
  说不成句子 = 断点在概念层（E 型），不是努力的问题。

## 9. 知识总表（卡在哪 → 缺什么 → 去哪补 → 怎么验证）

| 卡住时的表现 | 缺的知识 | 去哪补（中文） | 验证标准（做到=学会） |
| --- | --- | --- | --- |
| 签名里 `<T>` 不会写 | 泛型语法与边界 | 《Rust 编程之旅》第 10 章 | 闭卷写一个 `Vec<T: Ord>` 排序泛型函数 |
| `'a` 不知道该标哪 | 生命周期省略规则 | 搜「Rust 生命周期省略规则 中文」 | 给项目 3 个函数手标显式 `'a` 并编译通过 |
| `dyn Trait` 和泛型选不了 | 静态/动态分发、vtable | B3 分支 | 同一调用写两版都编译过，说出分发位置 |
| 不懂为什么需要 `Arc` | 引用计数、共享状态 | B4 分支 | 删掉 `Arc` 记录编译错误原话 |
| `.await` 后代码去哪了 | async 任务调度 | B5 分支 | 出口 3 题全对 |
| 自定义提取器不会写 | `FromRequestParts` 机制 | B6 分支 + 读 axum `extract.rs` | 闭卷手写 `OptionalAuthUser` 含 3 情形单测 |
| `query_as` 列怎么变字段 | sqlx 映射机制 | B7 分支 + `cargo expand` | 解释列名对不上时报编译期还是运行期 |
| 测试不会写、mock 不会做 | 测试基础 + trait 对象注入 | B8 分支 + 《Rust 编程之旅》第 11 章 | 写出第一条不连库的 service 测试 |
| `?` 不懂 | `Result` + `From` 转换 | B2 分支 | 禁用 `?` 写三层调用链再改回 |
| 闭包 / `move` 不懂 | 闭包捕获规则 | 《Rust 编程之旅》第 13 章 | 说清一个闭包捕获了哪些变量、按值还是按引用 |
| 模块不会拆、代码不知道放哪 | 分层职责 + 设计文档法 | 第 1 周职责清单任务 + 方法 4 | 给新功能写出一页设计文档 |
| 编译错误读不懂 | 错误结构 + 常见错误码 | 本手册 §5 | 看任意报错 30 秒定位缺的知识 |
| `#[derive(Serialize)]` 魔法定不了 | derive 宏原理 | 《Rust 编程之旅》第 19 章基础部分 | 说出 derive 展开后大致生成了什么 |
| 事务不会用 | ACID + Postgres 事务模型 | 搜「Postgres 事务 隔离级别 中文」 | 写一个「两语句要么全成要么全败」的测试 |
| 宏不会写 | `macro_rules!` | B14 分支 | 写出生成模块骨架的宏 |
| 不知道用哪个库 | 能力→工具映射 | 计划第四章工具包 + 本手册 §3 | 5 个常见能力 1 分钟说出 crate |

## 10. 卡壳周 SOP（标准动作，照做即可）

1. **分型**（5 分钟）：§1 四问，确定 A/B/C/D/E。
2. **记录**：`docs/踩坑记录.md` 记一行诊断结果。
3. **补知识**：查 §9 总表，限时 2–4 小时只补断点那一环（不是重学 Rust）。
4. **验证**：按总表「验证标准」列写最小例子，合资料完成。
5. **回任务**：用 §7 最小可写单元法回到原任务，一次一行一编译。
6. **复盘**：当天在 `docs/学习内容.md` 写一条教学复述——「教一个会 Python 的人懂这个点」。
   写不出来的地方 = 还没真正补上，下周重测。

**硬上限**：单个卡壳点最多占你半天。超了还卡 → 说明分型分错了，
或者该点属于【深】任务级别的深水区，记入 `docs/学习内容.md` 排到下周，先做主线别的任务。
