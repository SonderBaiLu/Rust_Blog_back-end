# 成为大能：项目之外的深入研究方向清单

> 定位：这份清单是**一年计划之外的「深造目录」**。一年计划解决「用 Rust 把真实项目做完」，
> 这份清单解决「理解项目底下的世界」。做完一年计划（或某个季度验收后）回来挑方向。
>
> 用法：
> - 每个方向按「分支」对待：限时 4–12 小时，先答自测题，答得上就跳过，答不上再进。
> - 自测题答得出 = 这个方向对你已经够用，不必深挖；答不出才值得花时间。
> - 资料给**中文搜索关键词**（和 `docs/学习计划.md` 第九章同款用法），搜不到中文时搜「概念名 + 中文解析」。
> - 顺序建议见文末「三条路线」，不用全做，按你的卡点和兴趣挑。

## 第一层：Rust 本体（从「熟练用户」到「懂 Rust 的人」）

### 1.1 Unsafe Rust 与 FFI

- **是什么**：`unsafe` 的五大风险（空指针、无效引用、数据竞争、未定义行为、跳过不变量）；用 FFI 调用 C 库（`bindgen` 生成绑定、`extern "C"`）；`no_std` 环境。
- **解锁的能力**：说清「内存安全」到底安全在哪、边界在哪；能接入现成的 C 库（很多高性能库只有 C 版本）。
- **自测题**：① `unsafe` 块里哪五类操作是编译器不再保证的？② 为什么 `Fn` / `FnMut` / `FnOnce` 三个 trait 要分开？
- **资料**：搜「Rust unsafe 使用原则 中文」「Rust FFI 指南 中文」；《Rust 黑魔法》前几章。

### 1.2 类型系统深潜（GAT / const 泛型 / proc-macro 内部）

- **是什么**：关联类型 vs 泛型参数（B13 的延伸）；GAT（泛型关联类型）解决什么问题；const 泛型；`proc-macro` 三件套（`syn` / `quote!` / `proc-macro2`）的内部机制——第 17 周的 `module_scaffold!` 是 `macro_rules!`，这一节是它的「进阶形态」。
- **解锁的能力**：看懂别人库的复杂 trait 约束；写自己的 derive 宏。
- **自测题**：① `type Item` 和 `<T>` 各自适合表达什么？② 宏为什么在类型检查**之前**展开？
- **资料**：搜「Rust GAT 泛型关联类型 中文」「Rust proc macro 教程 中文」。

### 1.3 异步运行时内核（B11 / B15 的延伸）

- **是什么**：`Pin` 为什么存在（自引用状态机）；`Waker` 内部结构；tokio 的 work-stealing 线程池；背压（backpressure）怎么设计；`async-trait` 宏到底改写了什么。
- **解锁的能力**：能解释「我的服务为什么慢」到运行时层面；能评价一个 async 库的设计。
- **自测题**：① 把一个 `Future` drop 掉会发生什么？② `Pin` 去掉会出什么问题（提示：自引用）？
- **资料**：搜「tokio 执行器 手写 中文」「Rust Pin 为什么 中文」；B 站「Rust async 原理」。

### 1.4 并发与内存模型

- **是什么**：`AtomicUsize` 的四种 ordering（`SeqCst` / `Acquire` / `Release` / `Relaxed`）；缓存行与伪共享；无锁队列入门；Rust 内存模型与 C++ 的对应。
- **解锁的能力**：写高性能计数器 / 限流器时知道该用哪种 ordering；看懂 `parking_lot` vs `std Mutex` 的差异。
- **自测题**：① 为什么单纯计数用 `Relaxed` 就够？② 两个相邻的 `AtomicUsize` 字段为什么可能互相拖慢？
- **资料**：搜「Rust 原子操作 ordering 中文」「缓存行 伪共享 中文」。

### 1.5 编译期深潜（可选，最硬核）

- **是什么**：NLL 借用检查的工作方式；trait 解析算法；`cargo expand` 系统用法；ZST（零大小类型）与 phantom 数据。
- **解锁的能力**：编译错误从「玄学」变成「可预测」；方法 2「预测先行」的命中率大幅提升。
- **自测题**：① 为什么 `&mut T: !Copy` 而 `&T: Copy`？② 泛型函数为什么每个具体类型都会重新生成一份机器码（monomorphization）？
- **资料**：搜「Rust NLL 借用检查 原理 中文」「Rust monomorphization 单态化 中文」。

## 第二层：操作系统与系统底层（后端「大能」的地基）

### 2.1 Linux 与系统调用

- **是什么**：文件描述符模型；`epoll` 为什么比 `select` 快；`io_uring` 的思路；`fork` / `exec` / 信号；`/proc` 里能读到什么。
- **解锁的能力**：看懂 tokio 底层为什么这样设计；能读懂 `strace` 输出排查问题。
- **自测题**：① `epoll` 的「就绪驱动」和轮询的本质区别？② 一个 Rust 进程里 `std::thread::sleep` 时线程在等什么系统调用？
- **资料**：《Linux 系统编程》（*The Linux Programming Interface* 中文版）；搜「epoll 原理 中文」。

### 2.2 内存管理

- **是什么**：`malloc` 家族（ptmalloc / mimalloc / jemalloc）的设计差异；Rust 的 `GlobalAlloc` 自定义分配器；arena / 池化分配；`Box::leak` 与内存泄漏检测（`miri`）。
- **解锁的能力**：性能瓶颈在「分配」时知道怎么办；能给项目换分配器并证明收益。
- **自测题**：① 为什么高频小对象分配要用 arena？② 给项目换 `mimalloc` 需要改哪几行、怎么验证？
- **资料**：搜「Rust 自定义分配器 GlobalAlloc 中文」「jemalloc 原理 中文」。

### 2.3 CPU 与性能基础

- **是什么**：缓存层次（L1/L2/L3）、分支预测、SIMD 入门、零拷贝（zero-copy）；为什么数据结构布局（SoA vs AoS）影响性能。
- **解锁的能力**：第 51 周压测找到的慢点，能解释到 CPU 层面。
- **自测题**：① 顺序读数组和乱序读数组差几倍，为什么？② 什么是「缓存行」，结构体 padding 解决什么？
- **资料**：搜「CPU 缓存 分支预测 中文」「零拷贝 原理 中文」。

### 2.4 网络协议栈

- **是什么**：TCP 三次握手 / 四次挥手、拥塞控制、TIME_WAIT；TLS 1.3 握手全过程（配合 rustls 源码）；HTTP/1.1 vs HTTP/2 vs QUIC；WebSocket 与 SSE 的区别（你的通知模块将来「实时推送」二选一）。
- **解锁的能力**：能解释「为什么偶发 504」「为什么延迟毛刺」；选对推送方案。
- **自测题**：① TLS 1.3 握手为什么只要 1-RTT？密钥是怎么交换的？② WebSocket 和 SSE 各自适合什么场景？
- **资料**：《Unix 网络编程》（Stevens，中文版）；搜「TLS 1.3 握手 过程 中文」「HTTP/2 多路复用 中文」。

## 第三层：数据库深潜（你天天用 Postgres，它值得被拆开看）

### 3.1 Postgres 内部机制 ⭐ 后端方向性价比最高

- **是什么**：MVCC（每行多个版本、`xmin`/`xmax`）；WAL 预写日志；vacuum 与膨胀；缓冲池与共享缓冲；锁的粒度（行锁 / 表锁 / 意向锁）。
- **解锁的能力**：解释「为什么我的表越来越慢」（膨胀）；设计时就知道隔离级别带来的坑。
- **自测题**：① `UPDATE` 一行其实做了什么（提示：不是原地改）？② 什么是「热链」（HOT chain）？③ 长事务为什么不回收旧版本？
- **资料**：《PostgreSQL 实战》（学习计划里已有）；搜「Postgres MVCC 原理 中文」「Postgres vacuum 膨胀 中文」。

### 3.2 查询优化与索引设计（B9 的延伸）

- **是什么**：`EXPLAIN (ANALYZE, BUFFERS)` 逐行读法；部分索引 / 覆盖索引 / 表达式索引；统计信息与代价估算；`JOIN` 策略（nested loop / hash / merge）。
- **解锁的能力**：第 51 周的「找 1 个慢查询」升级成「系统性地优化一组查询」。
- **自测题**：① 什么时候 B-tree 索引会失效（提示：选择性）？② 覆盖索引省掉了什么开销？
- **资料**：搜「Postgres 索引 设计 中文」「EXPLAIN ANALYZE 读法 中文」。

### 3.3 其他存储引擎对比

- **是什么**：SQLite（WAL 模式，正好服务你第 49 周的离线同步）；Redis 的事件循环与跳表；LSM-Tree（RocksDB）为什么写快读慢。
- **解锁的能力**：选型时说得出理由，而不是「大家都用」。
- **自测题**：① Redis 为什么单线程还快？② LSM-Tree 和 B-tree 的读写权衡在哪里？
- **资料**：搜「Redis 跳表 原理 中文」「LSM Tree 原理 中文」「SQLite WAL 模式 中文」。

## 第四层：分布式系统（博客是单人项目，但「大能」必须懂这些）

### 4.1 一致性与共识

- **是什么**：CAP 与 PACELC；线性一致性 vs 最终一致；Raft 算法（选主 / 日志复制）；复制与分片的基本问题。
- **解锁的能力**：看懂「分布式」三个字的真实代价；将来上多节点时不踩经典的坑。
- **自测题**：① 为什么「读写都走主节点」是线性一致的？② Raft 里为什么要有任期号（term）？
- **资料**：《数据密集型应用系统设计》（DDIA）——无官方中文版，搜「DDIA 中文 笔记」有完整整理；搜「Raft 算法 图解 中文」。

### 4.2 消息队列

- **是什么**：Kafka 内部（append-only log、分区、ISR、消费者组）；NATS 的轻量模型；队列在「解耦 / 削峰 / 审计」三种用途下的取舍。
- **解锁的能力**：你的「通知 / 提醒」如果量大了，知道该引什么、为什么。
- **自测题**：① Kafka 为什么消费快（提示：顺序写 + 零拷贝）？② 消费者组 rebalance 时发生了什么？
- **资料**：搜「Kafka 内部原理 中文」「Kafka 零拷贝 中文」。

### 4.3 分布式常用模式 ⭐ 和离线同步直接相关

- **是什么**：Outbox 模式（你第 49 周前端 outbox 的服务端对应物）；幂等设计（upsert 的完整形态）；2PC 为什么不用、Saga 怎么替代；令牌桶 / 滑动窗口限流（第 44 周频率限制的算法原理）；熔断器。
- **解锁的能力**：「幂等」从抄概念变成能设计；限流中间件能自己写。
- **自测题**：① 令牌桶和漏桶的区别？② 一个接口要做幂等，幂等键通常放在哪（请求头 / 参数 / 数据库唯一约束）？
- **资料**：搜「Outbox 模式 中文」「令牌桶 限流 实现 中文」。

## 第六层：性能工程（从「跑得快」到「证明它快」）

### 6.1 性能剖析（profiling）

- **是什么**：`perf` + flamegraph；`samply`（Rust 友好，支持 async）；`tracing` 的 span 数据怎么用；async 服务的剖析难点（任务 ≠ 线程）。
- **解锁的能力**：第 51 周压测之后，能定位「哪个函数、哪一行、为什么」。
- **自测题**：① 采样式 profiler 为什么比插桩式开销小？② async 代码里「CPU 占用低但延迟高」通常卡在哪？
- **资料**：搜「Rust 性能分析 flamegraph 中文」「samply rust async 中文」。

### 6.2 基准测试方法论（第 52 周 criterion 的延伸）

- **自测题**：① 为什么 benchmark 里要 `black_box()`？② 一次跑 1ms 和跑 1s 的基准，置信度差在哪？

### 6.3 架构级性能手段

- **解锁的能力**：性能优化从「微优化」升级到「结构优化」。
- **自测题**：① 连接池太小和太大分别出什么问题？② 什么数据适合放进程内 LRU，什么必须放 Redis？

### 7.2 API 设计深潜

- **自测题**：① 什么接口适合 SSE 而必须用 WebSocket？② 「契约先行」和「先写实现再补文档」各有什么代价？

### 7.3 事件驱动架构

- **自测题**：① 容器和虚拟机的本质区别（提示：隔离的是内核还是硬件）？② 多阶段构建省掉了镜像里的什么？
- **资料**：搜「Docker 原理 namespace cgroup 中文」「多阶段构建 原理 中文」。
